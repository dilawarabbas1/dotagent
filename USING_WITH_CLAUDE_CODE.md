# Using dotagent with Claude Code

This is the practical guide. For architecture see `PROJECT_CONTEXT.md`.

## TL;DR — three commands and you're done

```bash
pipx install dotagent           # one machine, once
cd ~/code/your-project
dotagent init                   # zero prompts; scaffolds .agent/, indexes docs/, renders CLAUDE.md
git add .agent/ CLAUDE.md .cursorrules .github/copilot-instructions.md AGENTS.md \
        .claude/hooks/post-tool.sh
git commit -m "chore: add dotagent context"
```

Open Claude Code in that repo. It auto-loads `CLAUDE.md`. Your AI agent now has:
project rules, ranked bug registry, anti-patterns, DB hotspots, Redis keys,
service dependency map, your personal style, current branch + recent files,
and the team's recent activity — every section pointing back to `docs/*.md`.

That's the whole base flow. Below: how each piece fits, plus what to do
when you want more.

---

## What Claude Code reads

When Claude Code starts in a dotagent-initialized repo it reads `CLAUDE.md`
(at the repo root, written by dotagent). That file is regenerated by
`dotagent sync` from these inputs, in priority order:

1. **`docs/*.md`** — your single source of truth. dotagent indexes it via
   `.agent/config.yaml` `sources:` and embeds top-N entries directly into
   `CLAUDE.md`. Path references are at the top of the generated file.
2. **`.agent/*.md`** — five project-wide files (style, rules, architecture,
   patterns, preferences) that supplement `docs/`.
3. **`.agent/memory/working/<actor>/current.json`** — your live session
   (branch, recent files, recent events) so the agent doesn't restart cold.
4. **`.agent/memory/episodic/...`** — recent team activity, filtered to the
   files you're currently touching.
5. **`.agent/memory/personal/<actor>/profile.yaml`** — your preferences,
   never shipped to teammates' generated files.

`docs/*.md` is never copied. dotagent only cites it.

## How edits in Claude Code feed back into context

Claude Code already supports tool/event hooks. `dotagent init` installs:

- `.claude/hooks/post-tool.sh` — fires `dotagent observe post-tool --tool claude_code`
  after every Edit/Write/Bash. That call:
  - appends a JSONL event to `.agent/memory/episodic/YYYY/MM/DD/<actor>__<session>.jsonl`
  - updates `.agent/memory/working/<actor>/current.json` (recent files, branch, last event)
  - if the touched file is `docs/*.md`, auto-reindexes sources so the next
    `dotagent sync` (or the next CLAUDE.md regeneration) picks up your edit.

Your git hooks (also installed automatically):

- `pre-commit` — fires `dotagent observe pre-commit --files <staged>`
- `post-commit` — fires `dotagent observe post-commit --sha <HEAD>`
- `prepare-commit-msg` — appends a `Co-authored-by: dotagent <... actor=alice tool=claude_code>`
  trailer so attribution survives in `git log` even on machines without dotagent installed.

Result: every Claude Code session, every commit, every `docs/*.md` edit is
captured. The next `dotagent sync` (or just the next CLAUDE.md re-render)
shows the updated context.

## The day-to-day commands you'll actually use

```bash
dotagent status                  # what dotagent knows about this repo right now
dotagent context                 # exactly what an AI agent sees (use --format markdown for full)
dotagent sync                    # rebuild CLAUDE.md / .cursorrules / etc. from latest sources
dotagent sync --dry-run          # diff what would change without writing
dotagent reindex                 # re-parse docs/*.md after manual edits
```

After a few sessions you'll want the visibility commands:

```bash
dotagent who --file services/auth/jwt.py         # which devs / AI tools touched this file
dotagent timeline services/auth/jwt.py           # full edit history of one file
dotagent activity --since 7d --by alice          # filtered event feed
dotagent feed --limit 50                         # team-wide chronological stream
dotagent leaderboard --since 30d                 # graduations / commits / events per dev
```

Your bug registry is a force multiplier for Claude Code:

```bash
# write or edit docs/bug-registry.md by hand → next sync surfaces top-N to CLAUDE.md
dotagent tool debug "$(cat trace.txt)"           # match a stack trace against past failures + bug-registry
dotagent tool checklist --since 14d              # pre-deploy checklist from rules + risk signals
dotagent tool memory "BUG-001"                   # search across all four memory stores
dotagent tool pattern-extractor --write          # static-analysis patterns into semantic memory
```

The agent learns through Auto-Dream:

```bash
dotagent dream run --since 30d                   # extract signals (revert clusters, repeat fixes, etc.)
dotagent dream list                              # see candidates awaiting review
dotagent dream graduate <id> --rationale "..."   # promote to a rule (rationale is MANDATORY)
dotagent dream reject <id> --rationale "..."     # reject (rationale is MANDATORY)
dotagent dream cron-install                      # daily 02:00 UTC auto-run
dotagent dream github-action                     # writes .github/workflows/dotagent-dream.yml
```

Skills (LLM-driven; needs `ANTHROPIC_API_KEY`):

```bash
dotagent skill list                              # observer / research / plan / code / review (+ your custom ones)
dotagent skill show plan --task "ship X"         # print resolved prompt without calling LLM
dotagent skill run plan --task "ship X"          # actually run it
dotagent skill pipeline observer plan code review --task "ship X"
```

## Recommended workflow inside Claude Code

1. **Start a new task in Claude Code.** It loads `CLAUDE.md` automatically — the
   four memories + your bug registry + anti-patterns are already in context.

2. **Set the task explicitly** (optional but high-leverage):
   ```bash
   # in a separate terminal
   dotagent observe task-start --tool claude_code --summary "ship JWT rotation fix"
   ```
   Now `dotagent context` shows the task; the next CLAUDE.md regen will too.

3. **Let Claude Code work.** Every Edit/Write/Bash fires the post-tool hook,
   which records the event and updates working memory.

4. **Before committing, ask Claude Code to consult the registries:**
   > "Use `dotagent tool debug` on this stack trace and incorporate any
   > bug-registry matches. Then run `dotagent tool checklist` and confirm
   > each item is satisfied."

5. **Commit normally.** The pre-commit hook records it; the
   `prepare-commit-msg` hook adds the dotagent trailer; the post-commit hook
   records the SHA.

6. **Periodically (weekly):**
   ```bash
   dotagent dream run                # extract signals from the last 30d
   dotagent dream list               # review candidates
   dotagent dream graduate <id> --rationale "..."   # promote good ones
   dotagent dream reject <id> --rationale "..."     # reject the rest
   dotagent sync                     # graduations flow into next CLAUDE.md render
   ```

## Migrating an existing Claude-Code-Optimization repo

You already have `docs/bug-registry.md`, `docs/anti-patterns.md`,
`docs/redis-key-registry.md`, `docs/db-impact-map.md`,
`docs/dependency-map.md`, plus `prompts/*.md` and `.claude/hooks/*.sh`.

```bash
cd ~/code/your-cco-project
pipx install dotagent
dotagent init --no-llm        # scaffolds .agent/ alongside your existing docs/
dotagent migrate-cco          # wires docs/ as sources, imports prompts/ into skills, ingests CLAUDE.md
dotagent sync                 # renders CLAUDE.md / .cursorrules / etc. with everything
```

Nothing under `docs/` is copied. Your `prompts/*.md` become
`.agent/skills/imported-<slug>.md`. Your existing `CLAUDE.md` content gets
parsed and routed into `.agent/{style,rules,architecture}.md` so hand-written
sections survive.

## Multi-developer + multi-AI-tool reality

dotagent records **identity (the human)** separately from **tool (the AI
platform)** on every event:

| Field    | Source                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------- |
| actor    | `~/.config/dotagent/identity.yaml` → fallback `git config user.email` → fallback OS user          |
| tool     | `--tool` flag on `dotagent observe` (`claude_code` / `cursor` / `copilot` / `opencode` / `cli`)   |
| host     | `socket.gethostname()`                                                                            |
| session  | UUID4-12 per invocation                                                                           |

Filesystem invariants that make multi-developer collaboration safe:

- **Episodic JSONL** filenames are `<actor>__<session>.jsonl`, partitioned by
  date directory → zero merge conflicts.
- **Semantic entries** use SHA1-prefixed slugs → zero collision across teammates.
- **Personal memory** lives at `memory/personal/<actor>/` and is **never merged**
  into other actors' adapter outputs.
- **Adapter outputs** (CLAUDE.md, .cursorrules, etc.) personalize per-actor on
  the developer's own machine — your `vim` preference doesn't leak into
  someone else's CLAUDE.md.

Teammate onboarding is one command:
```bash
pipx install dotagent
git pull
dotagent sync                 # personalizes adapters; identity = git config user.email
```

## Things to know about

- **Cache** at `.agent/.cache/sources.json` is **gitignored** — regenerated on
  `sync` / `reindex` / docs change. Pointer cards at
  `.agent/memory/semantic/sources/*.md` are committed.
- **`ANTHROPIC_API_KEY`** is optional. dotagent works without it (uses
  scaffolds for `init`, prints prompts for `skill run`). Set it for richer
  drafting and skill execution.
- **`docs/`** is sacred. dotagent never writes to it. If you want to maintain
  a separate "AI-only" doc, use a Custom Adapter: drop a Jinja template at
  `.agent/adapters/custom/templates/*.j2` with `{# output: docs/AI_CONTEXT.md #}`
  and enable `custom: true` under `adapters:` in `.agent/config.yaml`.

## What's *not* yet built (be honest)

- **Cursor hook shim** for Cursor < 0.40 (file-watcher fallback).
- **Copilot heuristic attribution** beyond the commit trailer (a VS Code
  extension would be needed for explicit attribution).
- **HDBSCAN + cosine embedding** for Auto-Dream — current implementation uses
  heuristic clustering (revert ≥ 2, repeat-fix ≥ 3, frequent-failure ≥ 3,
  cross-actor anti-pattern ≥ 2). Plenty good to start; embeddings are a
  Phase-5 polish item.
- **`dotagent server`** for centralized teams (real-time stream, RBAC,
  dashboards). Not in scope for the OSS package; happy to revisit.

Everything else from `PROJECT_CONTEXT.md` Phases 1-6 is implemented and tested.

## Quick troubleshooting

| Symptom                                                          | Likely cause / fix                                                  |
| ---------------------------------------------------------------- | ------------------------------------------------------------------- |
| `CLAUDE.md` doesn't update after editing `docs/bug-registry.md`  | run `dotagent sync` (or commit — the post-commit hook auto-fires)   |
| `dotagent who/activity/timeline` returns no rows                 | `dotagent reindex-events` to rebuild the SQLite index from JSONL    |
| `dotagent skill run` says "ANTHROPIC_API_KEY not set"            | `export ANTHROPIC_API_KEY=...` or use `--dry-run` to inspect prompts |
| Commit trailer not appearing in `git log`                        | check `.git/hooks/prepare-commit-msg` exists and is executable      |
| `migrate-cco` reported nothing                                   | your repo doesn't match Claude-Code-Optimization layout — manually   |
|                                                                  | populate `.agent/config.yaml` `sources:` to point at your docs       |
