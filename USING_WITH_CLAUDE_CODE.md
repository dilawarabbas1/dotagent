# Using dotagent with Claude Code

Practical session guide. For architecture see `README.md` and `docs/`.

## TL;DR — three commands and you're done

```bash
pipx install "git+https://github.com/dilawarabbas1/dotagent"
cd ~/code/your-project
dotagent init
git add .agent/ CLAUDE.md .cursorrules .github/copilot-instructions.md AGENTS.md \
        .claude/hooks/post-tool.sh
git commit -m "chore: add dotagent context"
```

Open Claude Code in that repo. It auto-loads `CLAUDE.md` — the **v3 navigation manifest** (default since v0.5.0). The four layers: reading protocol · workflow contract · hard policy · navigation index pointing at every `docs/*.md` and `.agent/*.md` file in the canonical schema.

---

## What Claude Code sees

`CLAUDE.md` (regenerated by `dotagent sync`) is a navigation manifest, not a content compendium. It points at:

1. **`docs/*.md`** — hand-maintained source of truth (bug-registry, anti-patterns, redis-keys, db-impact-map, dependency-map, architecture). dotagent never writes here.
2. **Hand-maintained docs convention** (optional) — if you opt in, `docs/feature_master.md` is the entry point; per-feature records (`FM-###-<slug>.md`) link to deep registries (`db-impact-map-*`, `redis-key-registry-*`, `bug-registry-*`, `ops/*`). See `docs/HAND_MAINTAINED_DOCS_CONVENTION.md`.
3. **`.agent/*.md`** — five project-wide files (style, rules, architecture, patterns, preferences).
4. **`.agent/memory/working/<actor>/current.json`** — your live session (branch, recent files).
5. **`.agent/memory/episodic/...`** — recent team activity, filtered to relevant files.
6. **`.agent/memory/personal/<actor>/profile.yaml`** — your preferences (never leaks to teammates' adapters).

Claude Code reads pointers and chases files on demand. Token cost stays bounded — typical project ~3K-40K tokens for the manifest, vs 80K+ for the legacy compendium.

To preview without writing: `dotagent manifest`.

## How edits feed back

`dotagent init` installs three hooks:

| Hook | Fires | What it does |
|---|---|---|
| `.claude/hooks/post-tool.sh` | every Edit/Write/Bash in Claude Code | `dotagent observe post-tool --tool claude_code` → episodic event + working memory update; reindexes if `docs/*.md` touched |
| `.git/hooks/pre-commit` | `git commit` | `dotagent observe pre-commit` → if `docs/*.md` staged, re-renders adapters (opt out: `hooks.auto_regen_on_docs: false`) |
| `.git/hooks/post-commit` | `git commit` | `dotagent observe post-commit --sha <HEAD>` → episodic event |
| `.git/hooks/prepare-commit-msg` | `git commit` | appends `Co-authored-by: dotagent <... actor=alice tool=claude_code>` trailer |

Every Claude Code session, every commit, every `docs/*.md` edit is captured. The next `dotagent sync` (or pre-commit auto-regen) refreshes CLAUDE.md.

## Day-to-day commands

```bash
dotagent status                  # what dotagent knows about this repo
dotagent context                 # exactly what an AI agent sees
dotagent sync                    # full regen (adapters + derived files + hooks)
dotagent sync --dry-run          # diff what would change

dotagent manifest                # preview the v3 manifest to stdout
dotagent manifest --diff CLAUDE.md   # show drift between disk and what would render

dotagent doc-coverage --files "src/a.py,src/b.py" --commit-msg "$(git log -1 --pretty=%s)"
                                 # required-doc checklist for a changed-file set
                                 # (HARD = FM-### claims · SUGGESTED = path heuristic · CHECK = always)
```

Visibility:

```bash
dotagent who --file services/auth/jwt.py    # which devs / AI tools touched it
dotagent timeline services/auth/jwt.py
dotagent activity --since 7d --by alice
dotagent feed --limit 50
dotagent leaderboard --since 30d
```

Bug registry / past failures:

```bash
dotagent tool debug "$(cat trace.txt)"      # match stack trace vs bug-registry + past failures
dotagent tool checklist --since 14d         # pre-deploy gate
dotagent tool memory "BUG-001"              # search the four memories
dotagent tool pattern-extractor --write
```

Auto-Dream (graduated rules):

```bash
dotagent dream run --since 30d              # extract signals
dotagent dream list                         # candidates awaiting review
dotagent dream graduate <id> --rationale "..."   # rationale MANDATORY
dotagent dream reject   <id> --rationale "..."
dotagent dream cron-install                 # daily 02:00 UTC
dotagent dream github-action                # nightly PR workflow
```

Skills (LLM-driven; needs `ANTHROPIC_API_KEY`):

```bash
dotagent skill list                         # observer / research / plan / code / review
dotagent skill run plan --task "ship X"
dotagent skill pipeline observer plan code review --task "ship X"
```

## Recommended Claude Code workflow

1. **Open Claude Code in your dotagent-initialized repo.** `CLAUDE.md` loads automatically — four invariant layers + schema-driven navigation. Claude knows the reading protocol, the workflow contract, the hard policy, and where every relevant file lives.

2. **Set the task explicitly** (optional, high-leverage):
   ```bash
   dotagent observe task-start --tool claude_code --summary "ship JWT rotation fix"
   ```

3. **Let Claude Code work.** Post-tool hook records every edit; working memory stays current.

4. **Before committing, ask Claude Code to consult the registries.** A useful prompt:
   > "Run `dotagent doc-coverage --files <changed files> --commit-msg <msg>` and address every HARD finding. Run `dotagent tool debug` on any stack traces. Run `dotagent tool checklist` and confirm each item."

5. **Commit normally.** The pre-commit hook auto-regenerates adapters if you touched `docs/*.md`. Attribution trailer added to the commit message.

6. **Periodically (weekly)**:
   ```bash
   dotagent dream run                # extract signals from last 30d
   dotagent dream list
   dotagent dream graduate <id> --rationale "..."
   dotagent sync                     # graduations flow into next CLAUDE.md render
   ```

## Project management — modules through dev↔QA cycle

```bash
dotagent project add-module "Auth"             # interactive Q&A → PLAN.md
dotagent project start 01-auth                 # cycle 1 opens
# ... dev work in Claude Code ...
dotagent project handoff 01-auth               # writes cycles/01/dev-handoff.md
# ... QA reads dev-handoff.md ...
dotagent project qa-record 01-auth --result pass|fail --rationale "..."
dotagent project resolve 01-auth               # ship after qa-pass; completion.md + HISTORY.md updated
```

`dotagent project regenerate` refreshes derived files without changing state. Use after pulling teammate changes that updated `module.yaml`.

## Migrating from Claude-Code-Optimization

```bash
cd ~/code/your-cco-project
pipx install "git+https://github.com/dilawarabbas1/dotagent"
dotagent init --no-llm        # scaffolds .agent/ alongside existing docs/
dotagent migrate-cco          # wires docs/ as sources, imports prompts/ into skills
dotagent sync                 # renders CLAUDE.md (+ sister adapters) with everything
```

Nothing under `docs/` is copied. `prompts/*.md` become `.agent/skills/imported-<slug>.md`. Existing `CLAUDE.md` content gets parsed and routed into `.agent/{style,rules,architecture}.md`.

## Multi-developer + multi-AI-tool

Every event records `actor` (the human) and `tool` (the AI) separately:

| Field | Source |
|---|---|
| `actor` | `~/.config/dotagent/identity.yaml` → `git config user.email` → OS user |
| `tool` | `--tool` flag on `dotagent observe` (`claude_code`, `cursor`, `copilot`, `opencode`, `cli`) |
| `host` | `socket.gethostname()` |
| `session` | UUID4-12 per invocation |

Filesystem invariants that keep multi-dev safe:

- **Episodic JSONL** filenames `<actor>__<session>.jsonl` → zero merge conflicts.
- **Semantic entries** use SHA1-prefixed slugs → zero collision.
- **Personal memory** lives at `memory/personal/<actor>/` and **never merges into other actors' adapter outputs.**
- **Adapter outputs** personalize per-actor locally — your `vim` preference doesn't leak into someone else's CLAUDE.md.

Teammate onboarding:

```bash
pipx install "git+https://github.com/dilawarabbas1/dotagent"
git pull
dotagent sync                 # personalizes adapters; identity = git config user.email
```

## Things to know

- **`.agent/.cache/sources.json` is gitignored** — regenerated on sync.
- **`ANTHROPIC_API_KEY` is optional.** Skills need it for real runs; everything else works without.
- **`docs/` is sacred.** dotagent never writes there. If you want an "AI-only" doc, use a Custom Adapter (`.agent/adapters/custom/templates/*.j2` with `{# output: docs/AI_CONTEXT.md #}` and `custom: true` in `adapters:`).
- **v3 is the default since v0.5.0.** To stay on v1: `render: { use_manifest: false }` in `.agent/config.yaml`.

## Quick troubleshooting

```bash
dotagent doctor                  # first line of defense
DOTAGENT_DEBUG=1 dotagent sync   # surface silenced exceptions
```

| Symptom | Likely cause / fix |
|---|---|
| `CLAUDE.md` doesn't update after editing `docs/*.md` | run `dotagent sync` (or commit — pre-commit hook auto-regens) |
| `dotagent who/activity/timeline` returns no rows | `dotagent reindex-events` to rebuild the SQLite index |
| `dotagent skill run` says "ANTHROPIC_API_KEY not set" | `export ANTHROPIC_API_KEY=...` or use `--dry-run` to inspect prompts |
| Commit trailer not appearing in `git log` | check `.git/hooks/prepare-commit-msg` exists and is executable |
| CLAUDE.md is v1 (compendium) after v0.5 upgrade | remove `render: { use_manifest: false }` from `.agent/config.yaml`, then `dotagent sync` |
| `migrate-cco` reported nothing | repo doesn't match CCO layout; manually populate `.agent/config.yaml` `sources:` |
