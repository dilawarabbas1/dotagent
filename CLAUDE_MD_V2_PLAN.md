# CLAUDE.md v2 — Redesigned structure

_Drafted: 2026-05-20 · Target: dotagent v0.5.0_

This plan replaces the current CLAUDE.md structure. The current one (v1)
is well-modularized but breaks at Aigent's scale: too long, identity-
dependent, identical for every task, churns git on every commit.

v2 keeps every strength (source-of-truth flow, per-section modularity,
conditional suppression) and fixes the five real problems:

1. No token budget — large projects overflow Claude's context window
2. Identity-dependent file (Personal section per-actor → git churn)
3. Volatile sections committed (Current state / Recent activity)
4. Static structure regardless of task
5. Duplication (FEAT-NN in Brief + Project + Active module)

---

## Goals

1. **Token-bounded.** Default budget: 25K tokens for the committed file.
   Per-section caps; never-truncate-this-section markers.
2. **Stable vs ephemeral split.** What's committed is project truth.
   What's local + volatile lives in a sidecar gitignored file.
3. **Task-aware rendering.** Same source files, but `--task <intent>`
   reorders + reweights sections.
4. **Zero duplication.** Each fact appears in exactly one section.
5. **Conflict-surfacing.** When docs disagree (the 22/23/28 problem),
   the conflict gets a `⚠ contradiction` marker, not a silent render.

## Non-goals

- Multi-format output beyond markdown
- LLM summarization of doc content (we curate; we don't summarize)
- Per-team variants (one project, one structure)

---

## Locked design decisions (D1–D8)

| # | Decision | Why |
|---|---|---|
| D1 | Split into `CLAUDE.md` (committed) + `CLAUDE.local.md` (gitignored) | Solves git churn + identity-dependence |
| D2 | Total budget for `CLAUDE.md`: **25,000 tokens**, configurable. Per-section soft caps that total ≤ budget. | Stops context overflow at scale |
| D3 | Stable 6-section structure. Order is fixed by design intent (cognitive priority), not by source. | Predictability — AI knows where to look |
| D4 | Task mode: `--task bug-fix \| design \| review \| qa \| onboard \| default`. Reorders priority weights only; never adds new sections. | Task-aware without explosion of variants |
| D5 | Conflict detection between sources runs at render time. Doc mismatches produce inline `⚠` markers + a Contradictions appendix. | Surfaces the audit findings WHERE the AI will see them |
| D6 | Truncation uses "head + middle-summary + tail" rule, not naive cut. Always preserves first + last item; replaces middle with `… (+N more in <source>)`. | Critical IDs at the boundaries stay visible |
| D7 | Every section has an explicit `<!-- section: <name> budget:<N> -->` marker for inspection and re-render tuning. | Auditable token accounting |
| D8 | `CLAUDE.local.md` is auto-generated on every `sync` and `.gitignore`'d by default; no per-actor commit churn. | Removes "two devs fight over CLAUDE.md" failure mode |

## Section structure — `CLAUDE.md` (committed file)

Six sections, in fixed order. Per-section budgets in parentheses.

```
[Header — never truncated, ~100 tokens]
[1. North Star — never truncated, ~500 tokens]
[2. Hazards (rules + active bugs + anti-patterns) — capped, ~3,500 tokens]
[3. Active work (project + active module) — capped, ~2,500 tokens]
[4. Technical truth (architecture + deps + redis + db) — capped, ~10,000 tokens]
[5. Sources catalog — link-only, ~500 tokens]
[6. Contradictions appendix — only if any, ~500 tokens]

(approximate total budget at default: 17,500 tokens, leaving ~7,500 for
free use in conversations within a 25K cap.)
```

### Header (~100 tokens)

```markdown
<!-- generated by dotagent v0.5.0 — do not edit. Re-render: `dotagent sync` -->
<!-- token-budget: 25000 · rendered-at: 2026-05-20T10:23:00Z · task: default -->
# Project context for Claude Code — `Aigent`
brief v3 · last reviewed 2026-05-01 · stage: beta · active actor: alice
```

### 1. North Star (~500 tokens · NEVER TRUNCATED)

The absolute essentials. Every session needs these.

```markdown
<!-- section: north-star budget:500 never-truncate:true -->
## North Star

**Vision:** Universal AI chat layer for solo founders.

**Business objectives:**
- OBJ-01 · Universal AI chat layer — 100 paying customers in 90 days
- OBJ-02 · Cross-tenant isolation — zero incidents year one
- OBJ-03 · Onboarding in 1 working day — NPS ≥ 40 at 30 days

**Hard rules (do not violate):**
- RULE-01 · Tenant isolation — every multi-tenant query filters by tenant_id
- RULE-02 · No PII to LLMs — redactor runs on every prompt
- RULE-03 · BYOK — never store user API keys server-side

**Non-goals:** Mobile native apps, federated SSO, self-hosted on-prem.
```

**Sources:** `.agent/project_brief.md` (Vision + OBJ + Rules + Non-goals).
**Order rule:** vision first, OBJs second, rules third, non-goals last.

```markdown
  ...

… (12 of 380 shown; full list: `docs/bug-registry.md`)

### Anti-patterns to avoid (top 8)
[curated from docs/anti-patterns.md]
- AP-005 · Logging PII fields directly — _rationale: GDPR Art. 5_
- AP-018 · Bypassing redactor in dev branch — _rationale: SOC2 commit_

```

**Sources:** `docs/bug-registry.md` (top N by severity × recency),
`docs/anti-patterns.md` (top N), `.agent/memory/semantic/rules/` (top N).

**Smart truncation:** preserve top 3 and bottom 1 in each list; replace
middle with `… (+N more)`. Active-conflict items pin to the top.

**Task-mode weighting:**
- `bug-fix`: budget 6,000 tokens; show top 25 bugs
- `design`: budget 1,500 tokens; show top 5 bugs
- `review`: budget 2,500 tokens; show top 10 bugs + patterns prominent

### 3. Active work (~2,500 tokens · cap)

What the AI is currently building.

```markdown
<!-- section: active-work budget:2500 -->
## Active work

### Project state
- Progress: 8/25 modules shipped (32%)
- In progress: M02-password-reset (cycle 02, round 2)
- Blocked: (none)

### Active module — `M02-password-reset`
- Implements: FEAT-02 (password recovery)
- State: in_progress · cycle 02 · round 2
- Cross-module: aigent-meta/01-password-reset-e2e

**Acceptance criteria:**
1. New password takes effect immediately, old sessions invalidated
2. Endpoint reveals nothing about whether email is registered
3. p95 reset endpoint latency < 200ms

**Read next:** `.agent/project/modules/M02-password-reset/cycles/02/contract.md`
_(in the middle of dev↔QA negotiation; round 2 of 3)_
```

**Sources:** `.agent/project/plan.yaml` (state summary),
`.agent/project/modules/<active>/module.yaml` + `PLAN.md` (active module).

**No more "all 25 modules listed."** Just project totals + the active
module's full detail. The full module table lives in §5 (Sources catalog).

### 4. Technical truth (~10,000 tokens · cap, biggest section)

Architecture + deps + DB + redis. The detail layer the AI needs to
reason about implementation.

```markdown
<!-- section: technical-truth budget:10000 -->
## Technical truth

### Architecture (this repo + active module's surface area)
[curated from .agent/architecture.md + docs/architecture.md;
 filtered to the active module's owned surface area]
- Service: aigent-backend (Python, FastAPI, Postgres + Redis)
- Active module's surface: services/auth/recovery/*, models/password_reset.py
- LLM gateway: not touched by this module
- Voice / WebRTC: out of scope (and brief lists as non-goal)

### Service dependencies
[from docs/dependency-map.md, filtered to active module's repo]
- aigent-backend → aigent-portal: REST /v1/auth/*
- aigent-backend → SendGrid: transactional email (FEAT-02 uses for recovery emails)

### DB hotspots (filtered to active module + RULE-01 surface)
[from docs/db-impact-map.md]
- users — RULE-01: queries must filter by tenant_id (HIGH risk)
- password_resets — new table for FEAT-02 (VERY HIGH; backfill policy)
- audit_log — every recovery attempt writes here

### Redis keys (active module's surface)
[from docs/redis-keys.md]
- session:{tenant_id}:* — invalidate on password change (RULE-02)
- recovery:tokens:{tenant_id}:{token} — TTL 1h; FEAT-02 owns

### Code style + patterns
[from .agent/style.md + .agent/patterns.md, abridged]
- FastAPI: response models always inherit from PydanticBase
- DB sessions: use async_session() context manager, never raw connections
```

**Sources:** `.agent/architecture.md`, `docs/architecture.md`,
`docs/dependency-map.md`, `docs/db-impact-map.md`, `docs/redis-keys.md`,
`.agent/style.md`, `.agent/patterns.md`.

**Critical change vs v1:** content is **filtered to the active module's
surface area** when one is set. Today CLAUDE.md dumps the whole
architecture every time. v2 shows the slice the AI is working on, with
a pointer to the full doc.

**Task-mode weighting:**
- `bug-fix`: filter to bug's cited files
- `design`: full architecture; no filtering
- `qa`: filter to active module's surface
- `onboard`: full + add overview commentary

### 6. Contradictions appendix (~500 tokens · only when not empty)

Surfaces doc-vs-doc and doc-vs-code drift inline.

```markdown
<!-- section: contradictions budget:500 -->
## ⚠ Contradictions detected (run `dotagent code audit` for resolution)

- **Agent count drift**
  - docs/architecture.md §2a says "22 task agents"
  - docs/dependency-map.md says "23 task agents"
  - .agent/architecture.md says "28 task agents"
  - _(Run `dotagent code crosscheck counts` to reconcile against actual file count.)_

- **Voice/PSTN status drift**
  - .agent/project_brief.md lists PSTN as a non-goal
  - docs/architecture.md §6 documents full voice architecture incl. PSTN
  - _(Strategic ambiguity — either update brief or annotate §6 as "documented for future".)_
```

**Suppressed entirely when clean** — most projects most of the time
won't have this section.

**Sources:** `dotagent code audit` results (v0.5.0+), structural
checker, plus a new internal `_detect_doc_contradictions()` pass that
runs at sync time.

## Section structure — `CLAUDE.local.md` (gitignored sidecar)

Local + volatile. Never committed. Per-actor.

```markdown
<!-- generated by dotagent — local-only, gitignored. -->
# Local context — `Aigent` (alice's view)

## Your personal preferences
- Editor: vim
- Favorite test framework: pytest
- Comment style: brief, no jsdoc
- (from .agent/memory/personal/alice/profile.yaml)

## Current state
- Current branch: feature/password-reset-v2
- Recent files touched (last 24h):
  - services/auth/recovery/handler.py
  - tests/auth/test_recovery.py
  - models/password_reset.py

## Recent team activity (last 10)
- 2026-05-19 22:31 alice (claude_code) — edit services/auth/recovery/handler.py
- 2026-05-19 21:14 bob (cursor) — commit "refactor user model"
- 2026-05-19 19:02 alice (claude_code) — edit tests/auth/test_recovery.py
- ...
```

**Critical:** this file is **regenerated every sync** + auto-added to
`.gitignore`. Two devs running sync produce different `CLAUDE.local.md`
files, but neither commits. Zero git churn from per-actor data.

## Task-mode rendering

`dotagent sync --task <intent>` reorders section budgets and weights
without changing structure.

| Task | Budget shift | Weighting change |
|---|---|---|
| `default` (no flag) | balanced as above | as above |
| `bug-fix` | Hazards 6,000 (up from 3,500); Technical 6,500 (down from 10K) | bug-registry sorted by file overlap with active edits |
| `design` | Hazards 1,500; Technical 11,000 (up); North Star 700 | full architecture; show all OBJ + FEAT |
| `review` | Hazards 2,500; Active work 4,500 (up); cite contracts | foreground modules' contract state |
| `qa` | Active work 4,500 (up); contracts inline | foreground current cycle contract |
| `onboard` | All sections soft-cap removed for first 50 lines | gentle intro tone; cite brief vision more prominently |

```bash
# Default render
dotagent sync

# Task-aware render
dotagent sync --task bug-fix
dotagent sync --task design --max-tokens 30000
```

## Conflict detection (Section 6)

Runs at sync time. Three sources of contradictions:

1. **Doc-vs-doc** — count mismatches between same claim across files
   (the 22/23/28 case). Detected by regex extracting counts + grouping
   by entity ("task agents", "services", etc.).

2. **Brief-vs-doc** — non-goal in brief contradicted by detailed
   architecture (the PSTN case). Detected by greping brief non-goals
   against indexed sources.

3. **Doc-vs-code** — surfaces v0.5.0+ code crosscheck results inline.

Detection is rough by design — false positives are acceptable. The
section just surfaces things to check; doesn't claim to be exhaustive.

---

## Truncation rules

When a section exceeds budget, apply this order:

1. **First** — preserve top-N (newest / most-severe / pinned) entries
   in full
2. **Middle compression** — replace middle items with
   `… (+M more in <source-path>) …`
3. **Bottom** — preserve last 1 entry to anchor "what's the lowest
   priority shown"
4. **Boundary** — first and last items always render; middle gets cut

Token accounting per section is precise: count tokens via tiktoken
(or character-based heuristic if tiktoken isn't installed). Refuse to
exceed budget; truncate at item-level.

## Backward compatibility

| Concern | Mitigation |
|---|---|
| Users on v0.4 expect old CLAUDE.md layout | `dotagent migrate` regenerates with v2 layout; old file gets backed up to `.agent/.imported/CLAUDE.md.v1` |
| Existing contracts cite specific section names | Section IDs are stable: `north-star`, `hazards`, etc. Keep these as anchors for any links. |
| Token budget config in `.agent/config.yaml` | New `render.max_tokens` field; defaults to 25000; absent = unbounded (today's behavior) |
| Personal section moved out of CLAUDE.md | New `CLAUDE.local.md`; readers know to load both for full local context |

The 480 existing tests stay green by default (the v2 renderer is
behind a flag until v0.5.0; once flipped, the v1 fixtures get updated).

## What this delivers concretely

Before (v1 today, Aigent):
```
CLAUDE.md  ~8,000–15,000 lines  ·  ~50–100K tokens  ·  unbounded
```

After (v2):
```
CLAUDE.md       ~600 lines  ·  ~17,500 tokens  ·  bounded
CLAUDE.local.md ~80 lines   ·  ~2,000 tokens   ·  gitignored
```

A 60–80% token reduction with **more focused content** — the AI sees
the active module's surface in detail, not the entire architecture
every time.
