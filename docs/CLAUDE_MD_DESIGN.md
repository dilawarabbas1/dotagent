# CLAUDE.md design

CLAUDE.md (and its sister adapters `.cursorrules`, `.github/copilot-instructions.md`, `AGENTS.md`) is a **navigation manifest** — it points an AI agent at the right files; it does not embed their content.

For implementation: `src/dotagent/render/manifest.py` + `src/dotagent/canonical_structure.py`.

---

## The four layers

```
Layer 1 — How to read this file   (invariant reading protocol)
Layer 2 — Workflow contract        (invariant; carries the OWNERSHIP RULE)
Layer 3 — Hard policy              (invariant never-violate list)
Layer 4 — Navigation manifest      (schema-driven per tier)
```

Layers 1–3 are byte-identical across every dotagent project (with placeholders like `{meta_branch}` substituted). Layer 4 is generated from the canonical schema.

### What CLAUDE.md is NOT

- Not the brief, plan, bug registry, or architecture doc.
- Not "what the AI sees" in total — the AI sees CLAUDE.md *plus* the files it points at, read on demand.

---

## The ownership rule

The load-bearing sentence of the entire design:

```
dotagent writes GENERATED files          You (Claude) write CONTENT files
─────────────────────────────────         ──────────────────────────────────
CLAUDE.md and sister adapters             docs/*.md (bug-registry, anti-patterns,
SCOPE.md, CONTRACTS.md                      redis-keys, db-impact-map,
contracts.md (project-root rollup)          dependency-map, architecture, …)
git.md (from git.yaml)                    .agent/architecture.md, rules.md, style.md
PLAN.md (from module.yaml)                Cycle artifacts (contract.md,
contract.frozen.md (post-freeze)            dev-handoff.md, qa-findings.md)
docs/service-registry.md (from git.yaml)  .agent/memory/personal/ (yours)
.agent/dashboard.md (state snapshot)
.agent/project/modules/<id>/HISTORY.md
```

Two simple rules:

1. A file with a `<!-- generated by dotagent -->` banner → **dotagent owns it.** Hand-edits get wiped on next sync.
2. No banner → **Claude (or you) owns it.** dotagent never touches it without explicit user action.

## Schema-driven manifest

Layer 4 is derived from `_PROJECT_ROOT_ENTRIES` / `_SERVICE_REPO_ENTRIES` / `_SINGLE_REPO_ENTRIES` in `canonical_structure.py`. Each entry declares:

```python
SchemaEntry(
    path="docs/your-doc.md",
    required=False,
    kind=KIND_FILE,            # or KIND_GENERATED / KIND_DIR
    category=CAT_ARCHITECTURE, # one of 25 categories
    when_to_read="What this is for. YOU update when X changes.",
)
```

That's it. The renderer auto-includes the pointer; coverage tests prove it's reachable.

### Coverage gates (CI-enforced)

`tests/render/test_manifest_coverage.py` enforces three invariants:

| Test | Guarantee |
|---|---|
| `test_every_schema_entry_has_a_category` | No entry defaults to `CAT_UNCATEGORIZED` |
| `test_every_non_hidden_entry_appears_in_manifest` | Every non-hidden entry produces a pointer line |
| `test_workflow_contract_present_in_every_manifest` + `test_hard_policy_ban_phrases_present` | The three invariant text blocks survive template edits |

If any fails, CI blocks merge.

## The tier model

| Tier | Detected by | What's distinctive |
|---|---|---|
| **project-root** | `.agent/git.yaml` present | Cross-repo navigation, project-wide modules, generated rollups |
| **service-repo** | `parent:` in `.agent/config.yaml` | `../`-prefixed inherited pointers (INHERITED marker); same workflow contract |
| **single-repo** | Neither | Flat; no inheritance, no cross-repo |

Same renderer (`render_manifest`) handles all three; the schema entries differ per tier. See `SERVICE_REPO_CLAUDE_MD.md` for service-repo specifics.

## How to extend

**Add a doc to the manifest** — add a `SchemaEntry` to the relevant tier's tuple in `canonical_structure.py` with a category. Done.

**Add a category** — add the constant + add to `ALL_CATEGORIES` + add `(CAT_X, "## Section header")` to `_CATEGORY_RENDER_ORDER` in `render/manifest.py`. Run tests.

**Add an invariant policy line** — edit `HARD_POLICY` in `render/workflow.py` + add an assertion to `test_hard_policy_ban_phrases_present`.
